# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An **internal GitHub repository hub** for the Cobblestone Learning team — it organises, showcases, and helps staff browse/reuse the [`cobblestonelearning`](https://github.com/cobblestonelearning) GitHub org's repositories and gists. Deployed as a **GitHub Pages site** at the org root (`https://github.com/CobblestoneLearning/cobblestonelearning.github.io`, live at `https://cobblestonelearning.github.io/`). The entire site is a single self-contained file: `index.html`. There is no build step, no package manager, no test suite, and no server-side code.

**It is NOT a marketing site.** Do not add sales/marketing copy (services, "request a quote", a sales contact band, etc.). The repos + gists and the tools to browse/reuse them are the point. It's still Cobblestone-branded (logo, palette, Montserrat) — keep the identity, not marketing.

## Deploying / previewing

- **Deploy:** commit to `main` and push. GitHub Pages serves `main` automatically — there is no build or CI stage to wait on.
- **Preview locally:** open `index.html` directly in a browser, or serve the folder (e.g. `python3 -m http.server`). It also resolves under the MAMP root at `http://localhost:8888/cobblestonelearning.github.io/`.
- Keep each commit scoped and describe what changed (e.g. "Hub: ..."). Commits are signed (see `Cobblestone/.gitidentity`).

Notes that matter when editing:
- Signed out, API calls are **unauthenticated** (GitHub's 60 req/hour-per-IP limit); signed in they use the viewer's token (5,000/hour). The code shows a branded empty/fallback state when rate-limited rather than leaving the sections blank.
- **Never list the organisation's repos with `/users/cobblestonelearning/repos`**: for an organisation it returns public repos only, even with a token. Use `/orgs/CobblestoneLearning/repos?type=all` (signed in) through `ghFetchAll`.
- If you swap a pinned CDN URL, **recompute its SRI hash** (`curl -s URL | openssl dgst -sha512 -binary | openssl base64 -A`) or the browser will block the resource.
- Modal content is injected via `innerHTML` from GitHub API responses; be mindful when touching the rendering code.
- **Demos never run as this page.** The demo viewer (`openDemo`) and the City's hologram use `sandbox` **without `allow-same-origin`**: a `srcdoc` frame with it runs in this page's origin, so a demo's code could read the visitor's token (scope `read:org repo`), and anyone who can commit a demo file to any repo could take it. `demoStorageShim` gives demos an in-memory localStorage/sessionStorage so they still work. Never add `allow-same-origin` back.
- **Paths from a card are checked** (`HX.safePath`): relative, inside the repo, no `..`, no scheme. A card cannot point the viewer's own GitHub access at other API endpoints.
- The page carries a meta Content-Security-Policy (`object-src 'none'; base-uri 'self'; form-action 'self'`). GitHub Pages cannot send headers, and a meta policy cannot set `frame-ancestors`.
- **Tailwind is a pinned copy** (`assets/vendor/tailwind/tailwindcss-3.4.17.js`, since 2026-11-20). `cdn.tailwindcss.com` sends no CORS header, so it could not carry an SRI hash, and a compromise of it could have read the token. Never point a page back at the unversioned CDN; see that folder's README to update it.
- **Shelves scroll sideways only** (`.hx-shelf-track` has `overflow-y: hidden`): a horizontal scroller that can also scroll vertically captures the mouse wheel and stops the page.
- **Project page hero is a slideshow** (`heroSlides`/`initSlides` in `hub-views.js`): the project's picture (`cover`, else the first gallery picture) when it has one, then the project in the City (the shared City instance, looking inside that repo; its canvas moves into the slide only while the slide shows, so it draws only then), then the building blocks waving on a loop (`.hx-slide.hx-loop`). It turns every 6 s (9 s on the City), holds while hovered or focused, and has previous, next, dots and a pause button. Reduced motion stops the turning and the wave. No WebGL: the City slide is left out.
- **One project count everywhere** (Bryan, 2026-11-23: the header said 126 and the City 119). A project is what `HX.list()` returns: no archived repos, no forks, one card per project (`HX.isCopy`). The header's Codebase card (`HX.updateHero`) counts that, organisation repos only whatever the scope, with **N more archived or forked** on the line under it (`#cin-x-repos`, hidden at 0). The City still draws archived repos as ruins, and its summary (`_summary` in `hub-city.js`) counts them after the projects: "119 projects in 9 neighbourhoods, plus 6 archived, shown as ruins". `cityItems` passes `archived` for that. Keep all three in step.
- **Card blocks wave on hover, each on its own rhythm** (`.hx-cb` in `HX.coverSVG`, with `--wd`, `--wdur` and `--amp` per block), like the blocks in the header.
- **Staff notes on a project page** keep a readable line length (820 px), with a sticky side panel (`notesSide`): a list of the notes' sections and where the notes live.
- **`html, body` use `overflow-x: clip`, not `hidden`.** `hidden` makes `body` a scroll container, and then the sticky header and the explorer bar silently stop sticking (fixed 2026-11-20).

## Authentication (Sign in with GitHub)

Public by default; signing in additionally surfaces private repos the viewer can access.

- **`CobblestoneLearning` is an organisation (since 2026-11-16).** The repos were moved to a new organisation, the old personal account was renamed `csl-bryan`, and the organisation took the `CobblestoneLearning` name, so every URL is unchanged.
- **The sign-in OAuth app ("Cobblestone Repository Hub", client ID in `AUTH_CONFIG`) is owned by the organisation** (moved from `csl-bryan` on 2026-11-17). This matters: the organisation restricts third-party apps, and only apps it owns get past that. While the app was owned by a person, signed-in staff saw public data only.
- **What loads (`loadRepos`):** signed out, `/orgs/CobblestoneLearning/repos?type=public`. Signed in, `/orgs/CobblestoneLearning/repos?type=all` (every repo the viewer can see; members see all, base permission Read), the viewer's own repos (`/user/repos?affiliation=owner`, flagged `_personal`), and their recent events (`/users/{login}/events`, the 3 pages GitHub keeps, asked for together: one after another they took 3.4 s and held up the list, which takes about 2 s) to flag org repos they pushed to (`_mine`). **Every list goes through `ghFetchAll`, which follows the `Link` header: there are more than 100 repos.** A failed signed-in org fetch falls back to the public list.
- **Organisation / Mine switch (`SCOPE`, `#scope-toggle`, persisted to `localStorage['cb_scope']`)**, shown only when signed in. `scopedRepos()` is the single source for the list, the chips and the counts: Organisation hides `_personal` repos; Mine shows `_mine`. Stats count organisation repos only. Cards carry a **Personal** badge and an access badge (Admin / Maintain / Write / Triage / Read, from `repo.permissions`).
- **Repo API paths use `repoFull(name)`** (the repo's `full_name`, preferring the organisation's copy) so personal repos open correctly. Do not hard-code `repos/cobblestonelearning/`.
- **Gists (`loadGists`):** organisations cannot own gists. Signed out, the section explains that; signed in it shows the viewer's own gists (`/gists`). The old shared gists are in the private repo `csl-gists`.
- **Manage link** (`#manage-link`) appears for owners and members of the `managers` team and opens https://cobblestone-manage.cobblestonelearning.workers.dev (repo `cobblestone-manage`: people, teams, access, activity). GitHub enforces the real permissions.
- A private-fetch failure must not break the public list.
- **Flow:** OAuth web flow via popup. `AUTH_CONFIG` (top of the main `<script>`) holds the public `clientId` + the worker `exchangeUrl` (both safe to commit). The popup redirects to `callback.html`, which `postMessage`s the `code` back (origin-checked + `state` CSRF check); the page POSTs the code to the Cloudflare Worker, which holds the **client secret** and returns the access token.
- **Backend:** `auth/worker.js` (+ `auth/wrangler.toml`) — does ONLY the code→token exchange; CORS locked to the Pages origin; secret set via `wrangler secret put GITHUB_CLIENT_SECRET` (never in the repo). One-time setup: `docs/AUTH-SETUP.md`.
- **Token handling:** the user token is held in `ghToken` and **persisted to `sessionStorage` (`cb_gh_token`)** so a page refresh restores the session instead of forcing a fresh OAuth round-trip (which GitHub challenges with a 2FA re-verification — the reason persistence was added). `sessionStorage` survives refresh/navigation but is **cleared when the tab closes**, keeping the exposure window small. On load, `restoreSessionThenLoad()` reads the stored token, **validates it via `/user`**, and either signs in (incl. private repos) or clears an invalid/revoked token; `signOut()` and a failed exchange remove it. All GitHub calls go through `ghFetch`, which adds the auth header when signed in. **Trade-off:** even in `sessionStorage`, a broad-scope (`repo`) token is readable by any XSS on this origin while the tab is open — keep the modal/innerHTML sinks sanitized, advise sign-out on shared machines, and prefer a least-privilege **GitHub App** (fine-grained, expiring 8-hour user tokens + refresh tokens) as the longer-term upgrade.
- **Never** put a token/secret in `index.html` — this is a public repo (GitHub secret-scanning auto-revokes committed secrets).

## Security model (swept 2026-11-20)

- **One origin for every Pages site.** Every Pages site in the organisation is served on `https://cobblestonelearning.github.io` (project sites at `/<repo>/`: only `subtitle-studio` since `new-csl-dash` was retired, its Pages site switched off and the repo made private on 2026-11-20), and they are all one origin. What was done about it (2026-11-20):
  - **The management page left this origin.** It is `cobblestone-manage` (a Cloudflare Worker with its own address, its own OAuth app "Cobblestone Hub Management" with expiring tokens and no wildcard callbacks, PKCE, real security headers). `manage.html` here only forwards. Never bring an `admin:org` flow back to this origin.
  - **Members cannot create Pages sites** (organisation setting `members_can_create_pages: false`). Keep project Pages sites to the deliberate list, and owners only.
  - **The hub's app asks only for `read:org repo`.** Its grants that included `admin:org` (from the old management page) were removed on 2026-11-20 by revoking all its user tokens, and its wildcard callback matching is off (all three pages use exactly `/callback.html`).
  - What is left: a page on this origin that an owner publishes (or a manager who gets write on `new-csl-dash` or `subtitle-studio`) can still reach the hub's `read:org repo` token. Treat write access to `subtitle-studio` as trusted.
- **Every page that holds a token** (`index.html`, `dashboard/`) hides itself when framed (clickjacking; Pages cannot send `X-Frame-Options`), accepts the sign-in message only from the popup it opened (`e.source`), and sends the token only to `api.github.com`. `callback.html` will not answer from inside a frame and clears the code from the URL and history.
- **`main` is locked to owners** (ruleset "Only owners change main", 2026-11-25, also on `subtitle-studio`): only owners can push to, delete or force-push `main`. Secret scanning and push protection are on for every public repo. Review notes are kept outside this public repo.
- **`manage.html` only forwards** (a meta refresh, no script). The page itself is in the `cobblestone-manage` repo.
- **`bryanslog/index.html` holds a token but nothing from the log** (`assets/fullpage.js`). It signs in, fetches the log with the viewer's own token and shows it in a sealed frame. It hides itself when framed, accepts the sign-in message only from its own popup, sends the token only to `api.github.com`, and accepts storage messages only from its own frame. A viewer without read access to `bryansLog` gets nothing from the log.
- **`lmsplan/index.html` and `networkreport/index.html` only forward** to their pages on https://cobblestone-private-pages.cobblestonelearning.workers.dev (`/lmsplan/`, `/networkreport/`) (one inline `location.replace`, passing on a `#section` that matches a strict pattern; a strict meta CSP; `noindex`; no-referrer). They hold no token and nothing from the projects; the Worker does the sign-in and the access check.
- **`dashboard/index.html`** escapes repo fields and accepts only `https://` homepages (a repo's homepage is free text any repo admin can set). Keep `cobblestone-gh-dashboard/index.html` identical.
- **The worker** (`auth/worker.js`, deployed 2026-11-20) validates the code and body size, sends `Cache-Control: no-store`, forwards the PKCE `code_verifier`, binds `redirect_uri` to `REDIRECT_URI` (the hub's `callback.html`), and has `POST /revoke`, which the pages call on sign-out. **The hub's sign-in uses PKCE** (`signIn`/`exchange` in `index.html`). Deploy with `cd auth && npx wrangler@4 deploy` (after `npx wrangler@4 login`).
